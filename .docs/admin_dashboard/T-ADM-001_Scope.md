# T-ADM-001 — Admin Dashboard Scope

## Document Control
- Task ID: `T-ADM-001`
- Owner: Product Manager Agent
- Date: 2026-04-23
- Milestone: `M8`

## Objective
Define the business and operational scope of the admin dashboard, including modules, KPIs, filtering, reporting, and export requirements, while keeping strict separation from public frontend flows.

## In Scope
- Operational admin interface under dedicated admin route tree (`/admin`).
- Read and export access to analytics data generated by:
  - `sessions`
  - `events`
  - `generation_logs`
- Admin modules:
  - Overview KPIs
  - Generation analytics
  - User analytics
  - Session analytics
  - Reports
  - Export center
  - System health panel
- Date-range filtering and pagination controls.
- Admin API auth with role/permission controls.

## Out of Scope
- Any redesign/refactor of public user journey (`/` and public components).
- Mutating user-facing business data from admin UI.
- New analytics schema expansion beyond existing MVP tables.
- Third-party BI integrations.

## Required KPIs
- Visitors (distinct sessions with page view event)
- Sessions
- Total generations
- Successful generations
- Failed generations
- Conversion rate
- Average generation time (ms)
- Rate-limited request count
- User summary: new, active, returning, downloads

## Reporting and Export Requirements
- Report types:
  - `overview`
  - `generations`
  - `users`
  - `sessions`
  - `full`
- Export formats:
  - `json`
  - `csv`
- Filters:
  - `startDate` / `endDate` (YYYY-MM-DD)
  - generation status (`success`)
  - `errorType`
- Export behavior:
  - explicit download action
  - no-store caching on responses
  - large query handling via pagination/limits

## Admin User Stories
1. As an operator, I can view top-level platform KPIs so I can assess current performance.
2. As an analyst, I can filter metrics by date range to compare periods.
3. As an operator, I can inspect failed generations and error types for incident triage.
4. As an admin, I can review user/session trends to evaluate engagement.
5. As an operator/admin, I can export report datasets as CSV/JSON for offline analysis.
6. As a security owner, I can confirm unauthorized users cannot access admin APIs.

## Information Architecture
- `/admin`
  - Auth gate (token input)
  - Filter bar
  - Overview KPI cards
  - Generation activity table
  - Users summary + trend
  - Sessions table
  - Reports & Export panel
  - System health panel

## Separation Rule (Public vs Admin)
- Public frontend remains in existing public route/component tree.
- Admin frontend uses dedicated route namespace (`/admin`) and dedicated client data layer.
- Admin API uses dedicated namespace (`/api/admin/*`) and never exposes data via public API contracts.

## Acceptance Criteria Mapping
- All dashboard modules explicitly listed: yes (see In Scope + IA).
- Required KPIs defined: yes (see Required KPIs).
- Export/reporting requirements clear: yes (see Reporting and Export Requirements).
- Admin scope separated from public frontend scope: yes (see Separation Rule + Out of Scope).
