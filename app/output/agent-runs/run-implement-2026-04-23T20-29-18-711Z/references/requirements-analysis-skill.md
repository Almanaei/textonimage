# Skill: Requirements Analysis

## Purpose
Transforms ambiguous stakeholder statements into explicit functional and non-functional requirements.

## When to Use
- project initiation
- scope clarification
- feature decomposition
- ambiguity reduction before technical design

## Inputs
- stakeholder brief
- business goals
- user constraints
- delivery scope

## Outputs
- clarified requirements
- assumptions register
- open questions list
- scope boundaries
- requirement traceability matrix

## Method
1. Extract goals, actors, and outcomes
2. Separate user needs from implementation preferences
3. Classify requirements into functional and non-functional categories
4. Surface hidden constraints
5. Convert vague statements into testable rules

## Quality Bar
- Requirements are testable
- Constraints are explicit
- Scope edges are documented
